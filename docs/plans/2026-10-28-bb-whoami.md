# `bb whoami` names the account and where its credentials come from

> `bb whoami` answers `unknown command`, and `bb auth status` names the account but not whether the token came from the environment or the keychain.

## Status

- **Phase:** Draft
- **Type:** feature
- **Sprint:** bb-cli-hardening
- **Issue:** #112
- **Review:** in-session
- **Impl:** same branch

## Changelog

- `bb whoami` prints the authenticated Bitbucket account and the credential source, never the token. It exits non-zero when no credentials work, and `--json` prints the same facts as JSON.

## Motivation

On 2026-10-28, while checking which identity a board and a script used, `bb whoami` answered `unknown command: whoami` (#112). `bb auth status [--json]` exists (`cli/bb:642`) and prints display name, username, account id and UUID, but nobody found it under that name.

It also omits two facts the ticket asks for:

- **Nickname.** Plot's `People` mapping, the board's «Mine» filter and every PR author comparison match on `author.nickname`. Here a nickname is a display name for some users (`Markus Ruepp`) and a handle for others (`jwloka`).
- **Credential source.** `bb_token` and `bb_email` read `BB_TOKEN` / `BB_EMAIL` first and fall back to the macOS keychain item `com.quatico.bitbucket-cli`. A shell with a stale `BB_TOKEN` speaks as a different account than the keychain, and nothing says which one answered.

## Design

### Approach

- Add `whoami` as a top-level command that runs `cmd_auth_status`. `bb auth status` stays.
- Text output, one fact per line: `nickname`, `display_name`, `account_id`, `credentials`. `credentials` is `BB_TOKEN env` or `keychain (com.quatico.bitbucket-cli)`, decided by the same order `bb_token` uses. The token and the email are never printed.
- `--json` prints `{nickname, display_name, account_id, uuid, credentials}` instead of the raw `/user` body. The raw body stays reachable through `bb api /user`.
- No credentials, or `/user` answers 401: one stderr line and exit 1, so `bb whoami >/dev/null` gates a script.
- Update `bb --help`, `bb auth status --help` and `skills/working-with-bitbucket-api/SKILL.md`.

### Open Points

- [ ] `--json` changes from the raw `/user` body to a projection. Search callers of `bb auth status --json` in this repo and in Plot before changing it; keep the raw body if any caller reads a field the projection drops.

## Notes

- `bb auth status` exits 0 when no response arrives (`BB_API_URL=http://127.0.0.1:9`, measured 2026-10-28), because `bb_api_call` treats HTTP status `000` as success. `bug/bb-transport-failure` in `bb-scripted-calls` fixes that, so this slice waits on it; without it `bb whoami` cannot keep its non-zero exit.
- #112 assumes credentials live under `~/.config/bb`. They live in `BB_TOKEN`/`BB_EMAIL` or the macOS keychain.
